# Token-budget 动态批处理设计

## 目标

在 DSW 的 Qwen3-VL 全参数 SFT 调试中，按每条样本的真实编码 token 数动态选择每卡 batch，提升短样本吞吐，并在送入模型前跳过当前单卡无法承载的超长样本。

本阶段只修改 DSW。DLC 保持每卡 batch 为 1，待 DSW 验证通过后另行启用分布式同步版本。

## 分桶规则

| 样本实际长度 | 每卡 batch | 处理方式 |
| --- | ---: | --- |
| 0–8192 | 4 | 训练 |
| 8193–32768 | 2 | 训练 |
| 32769–49152 | 1 | 训练 |
| 大于49152 | 0 | 跳过并计数 |

长度由当前 Qwen3-VL processor/template（处理器/模板）执行与训练一致的编码后获得，不使用字符数估算。`max_length` 保持81920，确保长度扫描能够识别49152以上的样本，而不会在扫描阶段因8192限制提前失败。

## 架构

在 `scripts/sft/` 新增独立的 token-budget batch sampler（批采样器）模块。模块包含：

1. 纯函数：根据 token 长度返回 batch 档位或跳过结论。
2. 长度扫描：通过 ms-swift 已包装的训练数据集读取编码结果，提取 `lengths` 或 `input_ids` 的真实长度。
3. 动态采样器：按桶内 batch 大小生成索引批次；每个 epoch 使用固定数据种子在桶内打乱，并再次打乱批次顺序。
4. 统计信息：记录各桶样本数、批次数、跳过数、当前批次大小和最大 token。

ms-swift 外部插件在 DSW 环境变量启用时替换 trainer（训练器）的训练 dataloader（数据加载器）。DLC 默认不启用该替换。

## 训练语义

- `gradient_accumulation_steps=1`。
- 每个优化步的样本数随桶变化，为1、2或4。
- 单个 batch 内只包含同一长度桶的样本，减少 padding（填充）。
- 超过49152 token 的样本不参与训练，写入统计日志，但不导致训练退出。
- DSW 继续训练5个优化步；若动态采样器产生的批次数不足5，Trainer 按现有行为进入下一 epoch。

## 日志与验收

启动时打印：

- 四个桶的样本数和批次数；
- 跳过样本数；
- 有效训练样本数；
- 分桶边界与对应 batch。

训练期间保留现有 loss、学习率、速度、ETA、GPU 利用率和显存日志，并增加当前 batch 档位与该批最大 token。DSW 验收要求：

1. 超过49152 token 的样本在模型 forward（前向传播）前被跳过；
2. 三个有效桶分别生成4、2、1大小的批次；
3. 每个样本在一个 epoch 内最多出现一次；
4. 固定 seed 下批次计划可复现；
5. 5 step 训练不因72k样本 OOM；
6. WandB 仍保持关闭。

## DLC 后续约束

DLC 版本必须由全局批次计划按 rank 等量切分，保证每个训练 step 中所有 rank 使用同一档本地 batch，并保持各 rank 的批次数一致。该部分不在本阶段实现范围内。
